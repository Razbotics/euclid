# Euclid — working conventions

## Start here

Read [`docs/`](docs/README.md) before making changes — it is the source of
truth for how this project works:

- [`docs/architecture.md`](docs/architecture.md) — system shape and the
  reasoning behind the load-bearing decisions
- [`docs/dev-setup.md`](docs/dev-setup.md) — env system, commands, gotchas,
  verification tools
- [`docs/mcp-tools.md`](docs/mcp-tools.md) — the agent-facing tool surface
- [`docs/plans/`](docs/plans/000-roadmap.md) — phased plans with task markers;
  `000-roadmap.md` is the current status of the whole project

If a doc contradicts the code, the code won: fix the doc as part of your change.

## Docs are part of the change, not a follow-up

**Every change updates the docs in the same commit.** A PR that changes
behavior and leaves the docs stale is incomplete. Concretely:

| What you changed | What to update |
|---|---|
| Architecture, a seam, a core decision | `docs/architecture.md` |
| Commands, env vars, ports, setup, tooling | `docs/dev-setup.md` |
| An MCP tool's name, args, or semantics | `docs/mcp-tools.md` |
| Finished plan work | flip `- [ ]` → `- [x]` in the plan file |
| Finished a whole phase | mark the phase `(status: done)`, update `000-roadmap.md` |
| Started significant new work | new plan `docs/plans/NNN-short-name.md` |
| Hit a non-obvious gotcha worth remembering | plan's "Notes / gotchas" section |

Plans use phases with task markers:

```
## Phase 2: TTS pipeline   (status: in progress)
- [x] TTS adapter interface
- [ ] Provider with word timestamps
```

Keep plan status honest — a task is `[x]` only when it's verified working,
not when the code is merely written. Completed plans stay in place as history.

## Engineering non-negotiables

- **Purity invariant**: `packages/engine` must stay a pure function of
  (document, time). Never use Date.now(), Math.random(), or accumulated
  state in the sampler or stage. Preview and export must stay pixel-identical.
- **All mutations are ops.** Never mutate a document directly — add an op to
  `packages/dsl/src/ops.ts` and handle it in the shared reducer. The DO, the
  editor, and MCP tools must all go through `applyOps`.
- **Schema changes**: `packages/dsl` is the contract for every app. Bump
  SCHEMA_VERSION on breaking document changes; keep Zod schemas and TS
  interfaces in sync (interfaces are explicit, not inferred, because of
  recursion in NodeSchema).
- **Workers must not import Pixi.** Pixi lives behind `@euclid/engine/pixi`;
  Workers import only `@euclid/engine` (the pure sampler).
- **MCP tools return cheap text** (outlines, ids, errors) so agent iteration
  stays free; only render/TTS spend credits.
- **Env**: root `.env` holds **production values with real keys** and is
  **never committed**; `.env.local` holds per-machine overrides only and is
  also never committed; `.env.example` is the committed template. Precedence
  is shell env > `.env.local` > `.env`. `.dev.vars` files are generated by
  `scripts/sync-env.mjs` — never hand-edit them, and restart the worker after
  changing secrets (wrangler does not reliably hot-reload them).
- **Never `git add -A` without checking what it sweeps in.** A real API key
  reached a commit that way. Prefer staging explicit paths, and check
  `git status` before committing.

## Definition of done

1. `pnpm -r typecheck` passes.
2. Behavior verified by running it, not by reading it — visual changes via
   `pnpm --filter @euclid/renderer exec tsx src/shot.ts <t...>` (read the
   PNGs); integration changes via the `check-*.ts` scripts in
   `apps/renderer/src`.
3. Docs and plan markers updated per the table above.
4. Report honestly: if something is unverified or partially working, say so.
